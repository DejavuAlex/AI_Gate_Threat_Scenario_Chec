# Feature Specification: AON结果及参数属性导出功能

**Feature Branch**: `feature/SML-8285-1.8.0`  
**Created**: 2025-11-25  
**Status**: Draft  
**Input**: 检验科医生需要导出AON结果和参数属性数据，包括参数计算结果、参数模拟和完整数据集，用于数据核对和评价指标计算

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导出参数计算结果数据 (Priority: P1)

**场景描述**：
检验科医生完成参数计算任务后，需要导出完整的计算结果数据进行离线分析和归档。

**用户操作流程**：
1. 用户在参数计算结果页面点击"导出"按钮
2. 系统生成包含两个Sheet页的Excel文件：
   - Sheet1: 参数属性（任务输入、参数信息、评价指标）
   - Sheet2: 数据集（检测结果、AON结果等）
3. 文件自动下载，命名格式：`系统检测项目_计算公式_计算任务编号_日期时间.xlsx`
   - 示例：`TEA_WMA_12345_20251125143022.xlsx`

**Why this priority**: 参数计算是核心业务流程，导出功能是数据分析和质量控制的基础需求

**Independent Test**: 
- 创建参数计算任务并完成计算
- 点击导出按钮
- 验证Excel文件包含正确的两个Sheet页
- 验证数据完整性和准确性
- 验证文件命名符合规范

**验收标准**：
- ✅ 导出的Excel包含两个Sheet页：参数属性、数据集
- ✅ 参数属性包含：任务输入内容、参数信息（靶值、SD、Error、Warning）、评价指标
- ✅ 数据集包含字段：条码号、系统检测项目、仪器模块名称、就诊类型、科室、检测结果、检测日期、检测时间、报警类型、AON结果（不含误差）
- ✅ 数据集中"含误差结果"、"AON结果（含误差）"为空
- ✅ "是否添加误差"字段值为"否"
- ✅ 文件命名正确：`系统检测项目_计算公式_计算任务编号_yyyyMMddHHmmss.xlsx`
- ✅ 导出全量数据，无分页限制

### User Story 2 - 导出参数模拟结果数据（不含误差） (Priority: P1)

**场景描述**：
检验科医生使用参数模拟功能验证不同参数组合的效果，需要导出模拟结果进行对比分析。

**用户操作流程**：
1. 用户在参数模拟页面设置模拟参数（误差选择"否"）
2. 完成模拟计算后点击"导出"按钮
3. 系统生成Excel文件（格式同参数计算）
4. 文件命名格式：`系统检测项目_计算公式_参数模拟结果_日期时间.xlsx`
   - 示例：`TEA_WMA_参数模拟结果_20251125143022.xlsx`

**Why this priority**: 参数模拟是参数优化的关键工具，导出功能支持多方案对比

**Independent Test**:
- 设置参数模拟（误差="否"）
- 执行模拟并导出
- 验证Excel结构和内容
- 验证数据与不含误差的参数计算结果一致

**验收标准**：
- ✅ 参数属性包含：系统检测项目、数据处理方式（数据对称转换、截断值处理）、数据源筛选条件、有效数据量、参数信息、评价指标
- ✅ 数据集结构与参数计算相同
- ✅ "含误差结果"、"AON结果（含误差）"为空
- ✅ "是否添加误差"值为"否"
- ✅ 文件命名正确：`系统检测项目_计算公式_参数模拟结果_yyyyMMddHHmmss.xlsx`

### User Story 3 - 导出参数模拟结果数据（含误差） (Priority: P1)

**场景描述**：
检验科医生需要模拟误差情况下的参数表现，导出含误差和不含误差的对比数据。

**用户操作流程**：
1. 用户在参数模拟页面设置模拟参数，误差选择"是"并输入误差值
2. 系统使用默认或自定义的误差值进行模拟
3. 完成模拟后点击"导出"
4. 系统生成包含完整误差对比数据的Excel

**Why this priority**: 误差分析是质量控制的核心功能，必须支持完整的误差数据导出

**Independent Test**:
- 设置参数模拟（误差="是"，输入误差值）
- 执行模拟并导出
- 验证Excel包含含误差和不含误差的完整数据
- 验证靶值、SD的对比数据

**验收标准**：
- ✅ 参数属性包含：含误差与不含误差的靶值、SD对比
- ✅ 数据集包含完整字段：条码号、系统检测项目、仪器模块名称、就诊类型、科室、检测结果、检测日期、检测时间、**含误差结果**、是否添加误差（是/否）、报警类型、AON结果（不含误差）、**AON结果（含误差）**
- ✅ "是否添加误差"字段正确标识："否"-不含误差，"是"-含误差
- ✅ 含误差数据完整填充，无空值
- ✅ 导出全量数据集

---

### User Story 4 - 误差值默认取值逻辑 (Priority: P2)

**场景描述**：
用户从不同入口进入参数模拟时，系统应智能提供合理的默认误差值，减少手动输入。

**用户操作流程**：
1. **场景A**：从计算结果页面/已绑定计算任务的质控参数/参数应用跳转到参数模拟
   - 系统默认使用**计算任务的TEa值**
2. **场景B**：从未绑定计算结果的质控参数/参数应用跳转到参数模拟
   - 系统默认使用**系统配置的TEa值**
3. 用户可以手动修改误差类型和误差值

**Why this priority**: 智能默认值提升用户体验，减少重复输入，但不影响核心功能

**Independent Test**:
- 测试场景A：从计算任务跳转，验证默认值=任务TEa
- 测试场景B：从未绑定任务的参数跳转，验证默认值=系统TEa
- 验证用户可以修改默认值
- 验证修改后的值正确应用到模拟计算

**验收标准**：
- ✅ 从计算任务相关页面跳转：默认误差值 = 计算任务的TEa
- ✅ 从未绑定任务的页面跳转：默认误差值 = 系统配置的TEa
- ✅ 用户可以修改误差类型（百分比/绝对值）和误差值
- ✅ 修改后的误差值正确保存并应用

---

### User Story 5 - 大数据量导出性能保障 (Priority: P2)

**场景描述**：
当数据集包含大量检测结果时（如数万条记录），导出操作应保持良好的性能和稳定性。

**用户操作流程**：
1. 用户触发导出操作
2. 系统显示导出进度（如果数据量大）
3. 系统分批处理数据，生成Excel文件
4. 导出完成后自动下载

**Why this priority**: 保障大数据量场景下的系统稳定性，但非最高优先级

**Independent Test**:
- 准备10,000条以上的测试数据
- 触发导出操作
- 验证导出完成时间在可接受范围内（如<30秒）
- 验证导出的Excel文件完整无损
- 验证系统资源占用正常

**验收标准**：
- ✅ 支持导出至少50,000条数据记录
- ✅ 10,000条数据导出时间 < 15秒
- ✅ 50,000条数据导出时间 < 60秒
- ✅ 导出过程中系统稳定，不影响其他用户操作
- ✅ 大文件Excel格式正确，可正常打开

## Functional Requirements *(mandatory)*

### FR1: 导出接口实现

**FR1.1 参数计算结果导出接口**
- 接口路径：`POST /api/v1/calculation-result/result/export`
- 请求参数：计算结果（JSON）
- 返回：Excel文件流
- 异常处理：任务不存在、无导出权限、数据异常

**FR1.2 参数模拟结果导出接口**
- 接口路径：`POST /api/v1/calculation-result/imitate/export`
- 请求参数：模拟参数（JSON）、是否包含误差
- 返回：Excel文件流
- 数据准备：导出前需调用模拟计算服务生成临时数据集和实时计算评价指标
- 异常处理：参数验证失败、模拟计算失败、数据生成异常

**FR1.3 导出文件格式**
- 文件格式：Excel 2007+ (.xlsx)
- 多Sheet页结构：
  - Sheet1: "参数属性" - 包含任务/模拟配置和评价指标
  - Sheet2: "数据集" - 包含原始检测结果和AON结果

### FR2: 参数属性Sheet内容

**FR2.1 参数计算结果的参数属性**
- 任务基本信息：任务编号、任务名称、创建时间、创建人
- 任务输入：数据集ID、系统检测项目、统计周期、TEA值、直方图类型、筛选条件（仪器模块、就诊类型、科室）
- 参数信息：计算公式、窗口期N、靶值、标准差、误差上限、误差下限、报警上限、报警下限、权重
- 评价指标：正常假阳率、正常真阴率、误差假阳率、误差真阳率、误差真阴率、误差假阴率、误差量中位数、误差量平均数、未识别误差量、未识别误差量百分比、误差量95分位数、误差量5分位数、不稳定指标

**FR2.2 参数模拟的参数属性**
- 基本信息：系统检测项目、模拟时间
- 数据处理方式：数据对称转换类型、Lambda值、截断值处理规则、截断值上限、截断值下限
- 数据源筛选：统计周期、仪器模块、就诊类型、科室、有效数据量
- 参数信息：同FR2.1，当模拟误差="是"时，靶值和SD分别展示含误差和不含误差的值
- 评价指标：同FR2.1

### FR3: 数据集Sheet内容

**FR3.1 数据集字段定义**
| 字段名称 | 数据类型 | 说明 | 参数计算 | 参数模拟（无误差） | 参数模拟（含误差） |
|---------|---------|------|---------|------------------|------------------|
| 条码号 | String | 检验单号 | ✓ | ✓ | ✓ |
| 系统检测项目 | String | 项目代码 | ✓ | ✓ | ✓ |
| 仪器模块名称 | String | 仪器模块 | ✓ | ✓ | ✓ |
| 就诊类型 | String | 门诊/住院/急诊 | ✓ | ✓ | ✓ |
| 科室 | String | 科室代码 | ✓ | ✓ | ✓ |
| 检测结果 | String | 原始结果值 | ✓ | ✓ | ✓ |
| 检测日期 | Date | 结果日期 | ✓ | ✓ | ✓ |
| 检测时间 | Time | 结果时间 | ✓ | ✓ | ✓ |
| 含误差结果 | String | 添加误差后的值 | NULL | NULL | ✓ |
| 是否添加误差 | String | 是/否标识 | 否 | 否 | 是或否 |
| 报警类型 | String | 正常/警告/危险 | ✓ | ✓ | ✓ |
| AON结果（不含误差） | Decimal | 原始AON值 | ✓ | ✓ | ✓ |
| AON结果（含误差） | Decimal | 含误差AON值 | NULL | NULL | ✓ |

**FR3.2 数据排序和过滤**
- **数据源为数据集（参数计算任务）**：按检测时间、条码号（barcode）正序排列
- **数据源为实时数据（参数模拟）**：按数据ID正序排列
- 导出全量数据，不应用分页限制
- 包含所有有效数据记录，不过滤任何状态

**FR3.3 异常值处理**
- 含误差结果中的异常值（负数、超大值）保留原始计算值，不做截断或修正
- 模拟场景下的异常值是误差影响的真实体现，用于分析极端情况
- 不因数值异常而拒绝导出或标记为错误

### FR4: 文件命名规则

**FR4.1 参数计算文件命名**
- 格式：`{系统检测项目}_{计算公式}_{计算任务编号}_{时间戳}.xlsx`
- 时间戳格式：yyyyMMddHHmmss
- 示例：`TEA_WMA_12345_20251125143022.xlsx`
- 特殊字符处理：文件名中的特殊字符替换为下划线

**FR4.2 参数模拟文件命名**
- 格式：`{系统检测项目}_{计算公式}_参数模拟结果_{时间戳}.xlsx`
- 时间戳格式：yyyyMMddHHmmss
- 示例：`TEA_WMA_参数模拟结果_20251125143022.xlsx`

### FR5: 误差值默认逻辑

**FR5.1 误差值来源优先级**
1. **用户自定义输入** - 最高优先级
2. **计算任务TEa值** - 从计算任务相关页面跳转时
3. **系统配置TEa值** - 从非计算任务页面跳转时

**FR5.2 误差值传递规则**
- 从计算结果页面跳转：读取计算任务的total_error_allowance字段
- 从已绑定计算任务的质控参数跳转：读取关联任务的total_error_allowance
- 从未绑定任务的质控参数/参数应用跳转：读取系统配置表的TEa值
- 用户修改后的误差值仅用于当前模拟，不影响原始任务数据

**FR5.3 误差类型支持**
- 百分比误差：以原始值的百分比添加误差
- 绝对值误差：直接加减固定数值
- 默认使用百分比误差

### FR6: 性能和安全要求

**FR6.1 性能要求**
- 10,000条数据导出时间 ≤ 15秒
- 50,000条数据导出时间 ≤ 30秒
- 1,000,000条数据导出时间 ≤ 60秒
- 支持异步导出（数据量>10,000条时）
- 导出操作不影响其他用户的正常使用
- 使用流式写入和分批查询优化大数据量性能

**FR6.2 安全要求**
- 导出操作需要验证用户权限
- 导出记录需要写入审计日志（操作人、时间、导出数据范围）
- 文件下载使用安全的临时URL（有效期5分钟）
- 数据脱敏：导出数据不含直接患者标识信息（如姓名、身份证），条码号为检验单号，无需脱敏处理

**FR6.3 错误处理**
- 数据不存在：返回404错误，提示"数据不存在或已删除"
- 权限不足：返回403错误，提示"无权限导出该数据"
- 数据量过大：返回413错误，提示"数据量超过限制（1,000,000条）"
- 系统异常：返回500错误，记录详细日志

**FR6.4 异步任务失败反馈**
- 异步导出任务失败时，返回通用错误消息和错误码给前端
- 错误码格式：`EXPORT_ERROR_xxx`（如EXPORT_ERROR_001表示数据查询失败）
- 详细错误堆栈和技术信息仅记录在服务端日志，不暴露给前端
- 审计日志记录完整的失败原因供管理员排查
- 前端展示用户友好的错误提示（如"导出失败，请稍后重试或联系管理员"）

## Key Entities *(optional)*

### 参数计算任务 (CalculationTask)
- **属性**：任务ID、任务名称、数据集ID、系统检测项目、TEA值、统计周期开始、统计周期结束、直方图类型、任务状态、创建时间、创建人
- **关系**：关联参数计算结果（一对多）

### 参数计算结果 (CalculationResult)
- **属性**：结果ID、任务ID、计算公式、窗口期N、靶值、标准差、误差上限、误差下限、报警上限、报警下限、权重、评价指标（多个字段）
- **关系**：属于参数计算任务（多对一）

### 模型数据 (ModelData)
- **属性**：数据ID、任务ID、条码号、系统检测项目、仪器模块、检测结果、映射结果值、检测日期、检测时间、状态、就诊类型、科室
- **关系**：属于参数计算任务（多对一）

### AON结果 (AonResult)
- **属性**：结果ID、参数ID、仪器模块、系统检测项目、监控结果开始ID、监控结果结束ID、AON结果值、AON结果时间、报警状态、处理状态
- **关系**：关联监控结果（多对多）

### 参数模拟配置 (SimulationConfig)
- **属性**：系统检测项目、数据转换类型、Lambda值、截断值上限、截断值下限、截断规则、窗口期、误差类型、误差值、是否含误差
- **用途**：临时配置，用于参数模拟计算

### 参数模拟临时数据集 (SimulationDataset)
- **属性**：数据ID、条码号、系统检测项目、仪器模块、检测结果、含误差结果、检测日期、检测时间、就诊类型、科室、是否添加误差
- **关系**：参数模拟有独立的临时数据集，与计算任务完全无关
- **生命周期**：模拟计算时生成，用于导出，不持久化存储

## Assumptions & Constraints *(optional)*

### 假设

**A1: 数据可用性**
- 假设计算任务和相关模型数据在导出时仍然存在于数据库中
- 假设相关的模型数据和AON结果已经计算完成
- 假设参数模拟数据为临时数据集，在模拟计算时生成，导出后即可丢弃

**A2: 用户环境**
- 假设用户使用的浏览器支持自动下载功能
- 假设用户设备有足够的存储空间保存导出文件（至少50MB）
- 假设用户安装了可以打开Excel 2007+格式的软件（MS Office / WPS / LibreOffice）

**A3: 系统配置**
- 假设系统配置了全局的TEa值作为默认误差参考
- 假设系统有足够的临时存储空间用于生成导出文件（至少10GB）

### 约束

**C1: 数据量限制**
- 单次导出最大支持1,000,000条数据记录
- 超过限制需要分批导出或使用数据筛选
- 建议常规导出控制在100,000条以内以获得最佳性能

**C2: 文件格式限制**

- 不支持旧版Excel (.xls) 格式
- 不支持CSV格式（未来可扩展）

**C3: 并发限制**
- 单个用户同时只能有1个导出任务在执行
- 系统级并发导出任务上限为20个

**C4: 数据保留**
- 导出的临时文件在服务器上保留时间为10分钟
- 用户下载后临时文件立即删除

**C5: 技术约束**
- 必须使用Apache POI库生成Excel文件
- 必须遵循项目宪章的安全要求（SecurityUtils验证）
- 必须记录审计日志（CDP Open API）

## Notes

### 设计决策记录

**DD1: 为什么使用两个Sheet页而不是两个文件？**
- **原因**：用户反馈希望参数属性和数据集关联查看，两个Sheet页更方便对照分析
- **优势**：减少文件管理复杂度，避免文件关联丢失问题
- **劣势**：单个文件较大，但在可接受范围内

**DD2: 为什么参数模拟的误差值默认取系统TEa而非计算任务的误差值？**
- **原因**：参数模拟的误差添加方式与计算任务不同（模拟需要指定误差方向，计算任务是随机添加）
- **考虑**：用户在模拟时通常会尝试不同的误差值，不需要复刻计算任务的误差设置
- **折中**：使用TEa作为参考，便于用户基于已知的允许误差范围进行模拟

**DD3: 为什么全量导出而不分页？**
- **原因**：数据分析和质量控制需要完整的数据集，分页导出会增加用户操作复杂度
- **风险缓解**：设置100,000条的上限，同时优化导出性能（异步处理、流式写入）

### 技术考虑

**TC1: Excel生成库选择**
- 使用Apache POI库的SXSSF（Streaming API）
- 优势：支持大数据量、内存占用低、性能好
- 注意：需要设置合理的内存窗口大小（建议1000行）

**TC2: 异步导出实现**
- 数据量>10,000条时，使用异步任务
- 前端轮询任务状态，完成后提供下载链接
- 任务状态：pending、processing、completed、failed
- 失败状态返回错误码和用户友好消息，详细堆栈仅记录服务端日志
- 错误码示例：EXPORT_ERROR_001(数据查询失败)、EXPORT_ERROR_002(Excel生成失败)、EXPORT_ERROR_003(文件存储失败)

**TC3: 文件存储**
- 使用临时文件存储导出结果
- 文件命名：`export_{userId}_{timestamp}_{uuid}.xlsx`
- 定时清理超过10分钟的临时文件
